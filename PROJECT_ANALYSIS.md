# Project Analysis — AI Medical Assistant (Laravel API)

_Generated by code analysis. Reflects the state of the `main` branch at the time of writing._

## 1. Overview

A Laravel 12 (PHP ^8.2) RESTful API backend for an AI-powered medical chatbot. Users register with a medical profile, open time-boxed "medical sessions," and exchange chat messages with an AI model. Auth is handled by Laravel Sanctum using bearer tokens (not SPA cookie auth — the `api` middleware group omits `EnsureFrontendRequestsAreStateful`).

- **AI provider**: Ollama Cloud, model `gemma3:27b-cloud` — not OpenAI or Anthropic.
- **Intended database**: PostgreSQL, per the README (columns use `jsonb`, `gen_random_uuid()`).
- **Actual default database**: SQLite — `config/database.php` and `.env.example` both default `DB_CONNECTION` to `sqlite`.
- **Frontend**: Inertia.js + React is wired into `composer.json`/`package.json`/`vite.config.js`, but no frontend source currently exists in the repo (see §5).

## 2. Domain Model & Database Schema

| Table | Primary Key | Notable Columns | Foreign Keys |
|---|---|---|---|
| `users` | `uuid`, default `gen_random_uuid()` | `full_name`, `gender` enum(male/female), `birth_date`, `email` (unique), `password`, `address`, `phone_number` (unique) | — |
| `profiles` | `bigint` auto-increment (inconsistent with rest of schema) | `blood_type` enum(A+/A-/B+/B-/AB+/AB-/O+/O-), `height_cm` int, `weight_kg` float, `chronic_diseases`/`allergies`/`current_medication`/`extra_info` as **jsonb** | `user_id` → `users.id`, `onUpdate('cascade')` only — **no `onDelete` rule** |
| `medical_sessions` | `uuid`, **no DB default generator** (must be app-set) | `status` enum(active/closed) | `user_id` → `users.id`, **cascadeOnDelete** |
| `messages` | `uuid`, **no DB default generator** | `role` enum(user/assistant) nullable, `content` longText nullable | `medical_session_id` → `medical_sessions.id`, **cascadeOnDelete** |

Standard Laravel infrastructure tables are also present and unmodified: `password_reset_tokens`, `sessions`, `cache`/`cache_locks`, `jobs`/`job_batches`/`failed_jobs`, `personal_access_tokens` (Sanctum, using `uuidMorphs` to match the UUID user PK).

**Relationships**: `User` 1—1 `Profile`, `User` 1—* `MedicalSession`, `MedicalSession` 1—* `Message`.

**Seeder issue**: `database/seeders/DatabaseSeeder.php` seeds a user with a `name` field, but the `users` table has no `name` column (it has `full_name`) and the migration requires several other NOT-NULL fields (`gender`, `birth_date`, `phone_number`, `address`) that aren't supplied. Running this seeder will likely fail or silently produce an incomplete row unless `UserFactory` compensates for all of it.

## 3. Controllers & Services

### `UserController` / `UserService`
- `register()` creates a `User` and its `Profile` in two separate calls with **no DB transaction wrapping them** — if profile creation fails after the user is created, an orphan `User` row with no profile results.
- `login()` returns asymmetric response shapes: success is `['status' => true, 'token' => ...]`, failure is `['status' => false, 'message' => ...]` — callers must handle both shapes since neither key set is shared.
- Several imports (`Auth`, `ValidationException`, `Str`, `PersonalAccessToken`) are unused.
- Failed login returns a generic "Email or password is incorrect" message without revealing which field was wrong — good practice.

### `ProfileController` / `ProfileService`
- `update()` and `show()` both throw a plain, untyped `\Exception('You do not have a medical file, please create your medical file first')` when the user has no profile.
- `bootstrap/app.php`'s `withExceptions()` closure is empty — there's no custom handler to turn this into a clean API error response, so it falls through to Laravel's default (likely a raw 500).
- `show()` hand-merges identity fields from `User` (full_name, gender, birth_date, email, phone_number) with medical fields from `Profile` into one flat response array.

### `ChatController` / `ChatService`
- Calls `https://ollama.com/api/chat` directly; both the base URL and model name (`gemma3:27b-cloud`) are hardcoded as private properties in `ChatService`, not sourced from config.
- Response handling passes the raw `Http` response object into `json_decode(...)`, relying on its implicit `__toString()` rather than calling `->json()` — works, but is non-idiomatic and fragile.
- **No error handling** for failed HTTP calls, non-200 responses, or unexpected payload shapes — a bad response would throw an undefined-array-key error rather than a clean failure.
- Persists both the user's message and the assistant's reply as `Message` rows.
- `TextCleanService` (normalizes markdown bullets, re-wraps broken sentences, collapses whitespace, is Arabic-punctuation aware) exists as a service but is **not called anywhere in `ChatService`** — worth confirming whether `ChatController` invokes it separately, or whether AI output currently goes un-cleaned.

### `SessionMiddleware` (aliased `medical.session`)
- If the user has no active `MedicalSession`, creates one.
- Expires sessions **30 minutes after `created_at`** — a fixed lifetime, not a sliding/idle-based timeout that would reset on activity.
- Mutates the in-memory collection when closing sessions rather than re-querying the database; this happens to work because Eloquent collections hold object references, but it's a subtle reliance on that behavior.
- Never blocks the request (no `abort()`); it purely manages session bookkeeping before calling `$next()`.
- Does **not** attach the resolved session ID to the request object, so `ChatController` must independently re-query the active session.

### Form Requests
- `RegisterUserRequest`: validates `full_name`, `gender` (enum), `birth_date`, `blood_type` (enum), `height_cm`/`weight_kg` (bounded), `chronic_diseases`/`allergies`/`current_medication` (required strings), `email` (unique), `password` (8–16 chars, confirmed), `address`, `phone_number` (unique, 8–10 chars), `extra_info` (nullable). Custom message key `password.confirmation` is a **typo** — Laravel looks up `password.confirmed`, so this custom message never actually fires.
- `profileRequest`: duplicates the same medical-field validation rules as `RegisterUserRequest` with no shared trait/base class to factor them out.
- `AuthUserRequest`: login validation — `email`, `password` only.

## 4. Routing

### `routes/api.php` (functional, working)
```
POST /register, POST /login                      (public)
auth:sanctum group:
  POST /logout
  PUT  /profile/update
  GET  /profile/show
  POST /chat/send   (+ medical.session middleware)
```
The only pending local change here is a whitespace-only diff (two blank lines removed, unstaged) — no functional difference.

### `routes/web.php` (broken)
- Imports and references `App\Http\Controllers\AuthController` for `/register`, `/login`, `/logout` — **this controller does not exist** anywhere in `app/Http/Controllers`. Hitting any of these web routes currently throws a fatal "class not found" error.
- `/home` is registered **twice**: once as an `auth`-gated closure rendering `Inertia::render('Home', ...)`, and again unconditionally via `HomeController@index`. The second (later) registration wins for routing/name resolution, which silently removes the intended auth protection on `/home`.
- Root `/` redirects to `route('home')`, so it inherits whichever `/home` definition actually resolves.

### `bootstrap/app.php`
- Registers the `medical.session` middleware alias → `SessionMiddleware`.
- Rebuilds the `api` middleware group as `[throttle:api, SubstituteBindings]` (confirming token-only auth, no stateful/SPA support).
- Appends `StartSession`, `ShareErrorsFromSession`, `ValidateCsrfToken` onto the `web` group (needed for the Inertia-rendered pages).
- `withExceptions()` is empty — no custom exception rendering is configured anywhere.

## 5. Frontend State

The `resources/` directory **does not currently exist**. Its only file, `resources/views/welcome.blade.php`, was deleted in commit `14f7b58`, and since Git doesn't track empty directories, the folder disappeared with it. However, `package.json` and `vite.config.js` both assume a React + Inertia SPA:
- `vite.config.js` points `laravel-vite-plugin` at `resources/js/app.jsx`, which doesn't exist.
- `package.json` lists `@inertiajs/react`, `react`, `react-dom`, `react-router-dom`, `laravel-precognition-react`, `bootstrap`, `tailwindcss`, `sass` as dependencies, with no corresponding source tree to consume them.
- `routes/web.php` calls `Inertia::render('Home', ...)`, which needs a `resources/js/Pages/Home.jsx` that isn't present.

Net effect: `npm run dev`/`npm run build` would fail today, and any request that reaches the Inertia-rendering code path would error.

## 6. Configuration & Environment

- `config/services.php`'s only custom entry is `services.ollama.key` ← `env('OLLAMA_API_KEY')`.
- `.env.example` is the **unmodified stock Laravel 12 skeleton** — it does not define `OLLAMA_API_KEY` at all, despite the README's own setup instructions telling a new developer to add it. A fresh clone following the README literally will have a silently broken chat feature until they notice this gap.
- `composer.json`: Laravel 12, Sanctum ^4.2, Inertia-Laravel ^2.0, plus `pear/http_request2` ^2.7, which appears to be an unused/vestigial dependency — the actual Ollama calls go through Laravel's `Http` facade (Guzzle-backed), not this PEAR library.
- Two empty, untracked, local-only directories exist with no discernible purpose: `camelTools/` and `.dist/`.

## 7. Tests

Only the default Laravel skeleton tests exist: `tests/Feature/ExampleTest.php` (asserts `GET /` returns 200) and `tests/Unit/ExampleTest.php` (trivial `true === true`). There is **no test coverage** of registration, login, profile management, chat, or the session-expiry middleware. Given the `routes/web.php` issues above, the Feature `ExampleTest` may itself be failing right now, since `/` redirects into the ambiguous duplicate `/home` route.

## 8. Git History & an Important Discovery

Local `main` has 8 commits, mostly README edits (clarifying session duration, adding a VPN-requirement note for Ollama Cloud) and the removal of the default Laravel welcome view.

**Key finding**: an unmerged remote branch, `origin/copilot/laravel-api-architecture-report`, contains a commit (`28b0577`, "feat: Implement Doctor and Appointment management system") representing a substantially more advanced version of this application that is **not merged into `main`**:

- New models: `Doctor`, `Appointment`, `Booking`, `Notification`, `Reminder` (plus edits to `User`).
- New controllers/services/requests for each of the above, plus `AdminController`/`AdminService` and `AdminMiddleware`.
- Role-based access via Spatie's `laravel-permission` package, with a `role`/`is_blocked` column added to `users`.
- New migrations for `doctors`, `appointments`, `reminders`, `notifications`, `bookings`, and the permission tables.
- New seeders: `AdminSeeder`, `RolePermissionSeeder`.

This branch reflects the project's actual intended direction (doctor booking, appointments, admin roles, notifications) far more than what's in the current `main` checkout. It's also the most likely explanation for an `Appointment.php` model briefly appearing in this session's initial git status — that work lives on this separate branch, not in the current working tree.

## 9. Summary of Notable Issues

1. `routes/web.php` references a non-existent `AuthController` — all web-based register/login/logout routes are currently broken.
2. Duplicate `/home` route registration silently drops its intended auth protection.
3. `.env.example` is missing `OLLAMA_API_KEY`, contradicting the README's setup instructions.
4. `UserService::register()` creates `User` + `Profile` without a DB transaction, risking orphaned users.
5. `ProfileService` throws generic untyped exceptions with no global exception handler configured.
6. A `password.confirmation` message-key typo in `RegisterUserRequest` means that custom message never fires.
7. Zero test coverage of any real application logic.
8. Frontend dependencies are declared but no frontend source code exists in the repo.
9. A materially more complete Doctor/Appointment/Admin feature set exists on an unmerged remote branch, not reflected in `main`.
